# GridGlyph Generators Package

The `generators` package follows a **Neuro-Symbolic** data generation pipeline. It uses the **Ground Truth** as a logical anchor, mutating it to create a massive, diverse training dataset while ensuring 100% mathematical consistency.

---

## 2. File Responsibilities

### `__init__.py` (The API)
**Primary Responsibility:** Public API Exposure.
- **Simplification:** Exposes the `build()` function as the single entry point.

### `build.py` (The Pipeline Runner)
**Primary Responsibility:** The "Assembly Line" & Validation.
- **Ground Truth Anchor:** By default, it uses `ground_truth.py` as the seed for generation.
- **Loop:** Iterates through rules, calls Mutators to expand them, and uses the `DSLExecutor` to calculate the `output_grid`.
- **Integrity:** Every sample in the `.jsonl` is verified; if the executor fails, the sample is discarded.

### `registry.py` (The Orchestrator)
**Primary Responsibility:** Mapping and Production Logic.
- **Seed-to-Logic Mapping:** Links DSL sigils found in the ground truth to their corresponding expansion logic in `mutators.py`.
- **Volume Control:** Defines how many variations (`multiplier`) to generate for each specific logic type.

### `mutators.py` (The Craftsmen)
**Primary Responsibility:** Logical Expansion (The "Rupture").
- **Rule Mutation:** Takes a ground truth rule (e.g., `↔`) and creates complex variants (e.g., `↔(⌂)` or nested commands).
- **Grid Mutation:** Generates new `input_grid` scenarios that obey the rule's constraints but vary in color, size, and noise levels.

### `primitives.py` (The Atomic Building Blocks)
**Primary Responsibility:** Numerical and Symbolic Foundations.
- **Grid Synthesis:** Core NumPy operations for drawing shapes and managing grid canvas.
- **Symbolic Translation:** Bidirectional mapping between integers (0-9) and DSL Roman numerals (I-X).

---

## 3. What the Dataset Contains

The generated dataset is a `.jsonl` file where each line is a self-contained training sample:
- **`dsl_rule`**: The symbolic string (e.g., `⧎(Ⳁ, ⊕(II,II,∅), ⊕(II,II,IX))`).
- **`input_grid`**: A 2D NumPy array representing the initial state.
- **`output_grid`**: The "Target" array calculated by the DSL Interpreter.

### Why this approach?
1. **Zero Hallucination:** Since the `output_grid` is generated by the actual code (Interpreter), the labels are 100% correct.
2. **Transversal Diversity:** By mutating the Ground Truth, we move the model from "Memorizing" specific grids to "Understanding" the underlying geometric transformations.
3. **Complexity Scaling:** We can generate simple 1x1 cases and ultra-complex nested operations using the same pipeline.
